What we learned from Productos

1. A working local build or direct wrangler deploy does not prove automatic Linux Git builds work. Vinext inherited Hostinger output:"standalone" and failed with Error: Failed to resolve required runtime dependency "__CLOUDFLARE_MODULE__CompiledWasm__" for standalone output. Vite now passes the shared Next config to Vinext with output:undefined; normal Next/Hostinger keeps standalone. Preserve the rest of the config. Check the FIRST actual build/deploy error, exact source, deployed version and whether the pipeline is direct or Git-triggered.
2. The earlier port intentionally exposed only three admin links because MySQL-dependent operations were blocked. Overnight work restores role-authorised menu visibility with explicit Pending routes to an authenticated availability page. This does not turn pending sections into working features. A good migration skill inventories every UI/route/action and detects missing capabilities BEFORE cutover; a green home page isn't enough. The existing Worker build-plugin guards unported actions even when their Server Action ID is posted to another allowed page. Do not remove those guards simply to make a menu appear normal.
3. D1 is SQLite, not drop-in MariaDB. Audit transaction callbacks, FOR UPDATE, unsigned subtraction, null-safe equality, fulltext, insert IDs, unique constraints, monetary integers, timestamp encoders, timezone/reservation expiration, migrations and atomic batches. Never imitate a transaction with unrelated non-atomic writes. Hyperdrive with an external MySQL/MariaDB DB is an alternative, but verify current driver/session/prepared-statement semantics and exact auth/TLS/connectivity requirements from primary docs and runtime tests. Not all apps should be rewritten to D1.
4. Workers is an isolate runtime with Node compatibility, not an always-running next-server process. Inspect native binaries, fs access (virtual/runtime support depends on current API/date; no assumption of a durable host filesystem), child_process, sockets, process globals, memory, bundle size, streaming lifetime, timers, scheduled jobs and request-scoped env/database/session contexts. Verify current official Node compatibility docs; don't repeat blanket outdated claims such as all node:fs is unsupported. Review Vinext vs OpenNext against the actual Next version/features and supported provider documentation. We use Vinext here; it is not a universal adapter requirement for other repos.
5. Image resizing is performed locally with existing tooling. R2 stores the pre-sized responsive files. Verify src/srcset, image dimensions/transferred bytes, WebP/JPEG fallback, OG images, alt text and CDN headers; preserve the existing bucket/references. Never reupload all media or purchase Cloudflare Images just because a frontend moves.
6. Custom Domain route/DNS/TLS is separate from nameservers and proxy toggle. Record both origin records before cutover, configure build/runtime URL, canonicals, robots, sitemap, redirects, cookies, Server Action origin checks and rollback. Keep the preview noindex; live public routes indexable; admin/private responses no-store/noindex. Avoid shared caching of cookie/auth/RSC/flight/action responses. A public anonymous HTML cache may be considered only with explicit eligibility/sanitisation, invalidation, price/stock freshness and security tests. Do not override framework private/no-store indiscriminately.
7. Resources and capacity: current official Workers Paid allowances: 10 million requests / 30 million CPU ms monthly; extra $0.30 per million requests and $0.02 per million CPU milliseconds. Builds, D1, R2, logs, email have separate allowances. Paid per-invocation seconds ceiling, free 10 ms CPU ceiling and monthly 30 million ms budget are different. CPU is not network/database wall latency. Visits are not unique visitors or requests. An example of 5 pages/visit × 2 dynamic requests/page gives 50,000 visits at 60 ms/request before other account use, but it's a scenario. At 100,000 visits in that scenario CPU overage is about $0.60, not hundreds of dollars. Verify fresh prices/limits, alert/usage controls, shared account usage and query/operation amplification; never promise a universal hard $5 cap.
